# Path Builder (지오메트리 대시 Geode 모드, 안드로이드)

에디터 플레이테스트에서 지나간 경로를 기록하고, 그 경로를 기준으로 블럭·가시를 자동 배치하는 모드입니다.

## 동작 방식
1. 에디터에서 **플레이테스트**를 시작하면 자동으로 기록됩니다 (위치, 게임모드, 중력 방향, 바닥 접촉, 클릭, 미니 크기).
   - 죽으면 그 직전까지만 기록됩니다. 새 플레이테스트를 시작하면 이전 기록은 지워집니다.
2. 플레이테스트를 멈추고 왼쪽의 초록색 **AUTO** 버튼을 누르면 배치됩니다.
3. 회색 **SET** 버튼으로 설정 창이 열립니다.
4. **BOT** 버튼(켜지면 하늘색)을 켜고 플레이테스트하면, 마지막으로 직접 플레이한 클릭을 **같은 물리 단계에 그대로** 재생합니다. 에디터 플레이테스트에서만 작동합니다.
   - **이어서 녹화**: 봇이 재생하는 중에 화면을 터치하면 그 순간부터 직접 조작하고, 그 앞 클릭은 그대로 둔 채 뒤만 새로 녹화됩니다. 저장된 클릭이 끝나면(지난 녹화를 죽기 전에 STOP으로 끝낸 경우) 자동으로 조작이 넘어옵니다. 긴 맵도 여러 번에 나눠 녹화할 수 있습니다. (SET의 Tap to Take Over로 끌 수 있음)

5. 분홍색 **CHK**(프레임퍼펙트 검사): 저장된 클릭을 하나씩 **물리 한 단계(240 TPS면 1/240초, 피직스 바이패스를 쓰면 그 TPS의 한 단계) 앞뒤로** 밀어서 자동으로 플레이테스트하고, 그래도 살아남는 클릭을 알려줍니다. 먼저 원래 클릭 그대로 통과하는지 확인하고, 못 통과하면 "통과 불가"를 알려줍니다. 다시 누르면 취소됩니다.

6. 보라색 **SIM**(오브 자동 클릭): 직접 놓은 오브를 봇이 대신 눌러주는 기능. 순서:
   1) 오브를 배치  2) BOT 끄고 오브 위를 **지나가기만** 하면서 대충 플레이  3) **SIM** → 봇이 그 클릭을 다시 재생하면서 오브에 겹치는 순간마다 눌러 오브를 탐(누르고 있던 중이면 잠깐 뗐다가 다시 누름). 그 결과가 새 기록(클릭+경로)으로 저장됨  4) **AUTO**(tight)로 가시 배치  5) **CHK**
   - 닿지 못한 오브와, 도중에 죽은 경우 위치를 결과 창에 알려줍니다.

버튼은 음악 버튼 옆에 세로로 AUTO / SET / BOT / CHK / SIM 순서로 있습니다.

**듀얼 모드**: 듀얼 포탈 구간에서는 두 플레이어 경로를 각각 기록하고, AUTO는 플레이어마다 따로 배치한 뒤 다른 플레이어 경로에 닿는 것은 빼고 놓습니다. BOT/CHK/쇼케이스 봇은 탭 한 번이 두 플레이어 모두에 들어가는 실제 게임 동작을 그대로 따르고, 레벨 설정에서 **2-Player 모드**를 켠 경우엔 플레이어 2 쪽 클릭도 따로 기록·재생합니다. (SIM은 아직 플레이어 1의 오브만 처리)

직접 플레이한 클릭은 레벨별로 저장되어, 게임을 다시 켜도 BOT과 CHK에서 그대로 쓸 수 있습니다.

## 쇼케이스 봇 (실제 플레이)
SET의 **Showcase Bot (real play)**를 켜면 레벨을 실제로 플레이할 때 저장된 클릭을 재생합니다.
- 켜져 있는 동안 **세이프 모드 강제**: 진행도 0% 유지, 클리어·별·코인·시도·점프 횟수 저장 안 함, 레벨 검증(verify) 안 됨
- 연습 모드, 스타트 포지션, 플랫포머에서는 봇이 작동하지 않습니다 (세이프 모드는 유지)

## 배치 규칙
| 모드 | 배치 |
|---|---|
| 큐브·로봇 | 서 있던 곳 아래 발판, 점프한 구간의 출발 지면에 가시 (공중 발판이면 받침 블럭 추가) |
| 볼·스파이더 | 바닥/천장 발판, 중력 전환으로 떠난 면에 가시 (천장 가시는 180° 회전) |
| 쉽·스윙·UFO | 경로 위아래로 여유(margin)를 둔 통로 블럭, 높이가 바뀌는 곳은 벽으로 연결 |
| 웨이브 | 쉽과 같지만 더 좁은 통로 |

모든 블럭과 가시는 **기록된 매 프레임의 플레이어 히트박스와 겹치지 않는지** 검사한 뒤에만 놓입니다. 이미 블럭·가시가 있는 칸은 건드리지 않습니다.
배치된 오브젝트는 **되돌리기 한 번**으로 전부 취소되고, 배치 직후 전부 선택된 상태라 바로 옮기거나 지울 수 있습니다.

## tight 스타일로 직접 만든 레이아웃 덮기
경로를 녹화한 뒤 블럭 레이아웃을 직접 만들어도 됩니다. tight로 AUTO를 누르면 큐브를 포함한 모든 모드의 경로 위아래에 가시와 톱니가 붙고, 직접 쌓은 블럭 안에 들어가는 자리는 건너뜁니다.

## 설정 (SET)
- **Placement Style**: `basic`(기본) / `dense`(가시 빽빽, 통로 좁게) / `blocks-only`(가시 없음) / `tight`(가시만, 격자 무시하고 실제 히트박스에 픽셀 단위로 붙임)
- **게임모드별 켜기/끄기**: Cube, Ship, Wave, Ball, UFO
- **Spikes per Jump**: basic에서 점프당 최대 가시 수
- **Spike Clearance (blocks)**: basic/dense에서 가시와 플레이어 사이 여유 (칸 단위, 1 = 1격자)
- **Tight Gap (px)**: tight에서 가시와 플레이어 히트박스 사이 간격 (프리무브 픽셀 단위, 30px = 1칸, 0 = 맞닿음)
- **Portal Gap (px)**: tight에서 포탈·속도 포탈·발판·중력/크기 변경 지점 앞뒤에만 쓰는 간격 (기본 1px). 나머지 구간은 Tight Gap
- **Tight Pattern**: `chain`(기본, 정돈된 배치: 같은 크기 톱니를 일정 간격으로 위아래 엇갈려 놓고 그 사이를 같은 크기 미니 가시로 촘촘히 채움) / `random`(예전처럼 톱니·가시 랜덤 섞기, 크기도 랜덤)
- **Saw Spacing (px)**: chain에서 한쪽 줄의 톱니 사이 간격 (톱니 지름 정도로 하면 톱니가 붙은 사슬, 0 = 톱니 없음)
- **Saw Size / Spike Size**: chain에서 모든 톱니·가시의 크기 (가시 기본 0.5 = 미니)
- **Saw Chance (%)**: random에서 가시 사이사이에 톱니가 섞이는 비율 (0 = 가시만)
- **Saw Object IDs**: 쓸 톱니 ID 목록 (기본 88,89,98, chain은 첫 번째만 사용). 원형 판정 크기는 게임에서 읽어옴
- **Min / Max Size**: random에서 가시·톱니 크기를 이 범위에서 랜덤으로 (둘 다 1이면 기본 크기)
- **Tight Spike Spacing (px)**: tight에서 가시 사이 가로 간격 (픽셀 단위, 작을수록 촘촘)
- **Ship/UFO, Wave Corridor Margin (blocks)**: 통로 위아래 여유 (칸 단위)
- **Block / Spike Object ID**: 사용할 오브젝트 ID (기본 1 / 8)

## 빌드 방법 (.geode 파일 만들기)
PC나 휴대폰 브라우저에서 할 수 있습니다.
1. GitHub에서 새 저장소(Repository)를 만듭니다.
2. 이 폴더의 파일을 전부 업로드합니다. (`.github/workflows/build.yml` 경로가 그대로 유지되어야 합니다)
3. 저장소의 **Actions** 탭에서 빌드가 끝나기를 기다립니다 (약 5~10분).
4. 완료된 빌드의 **Artifacts → Build Output**을 받으면 안에 `heum.path-builder.geode`가 있습니다.

## 설치
1. 안드로이드에 **Geode 런처**가 설치되어 있어야 합니다.
2. `.geode` 파일을 Geode 모드 폴더에 넣거나, 게임 안 Geode 메뉴에서 파일로 설치합니다.
3. 필요 모드 **Node IDs**는 Geode가 자동으로 받아줍니다.

## 대상 버전
- Geometry Dash **2.2081**, Geode SDK **5.11.2**
- GD가 더 새 버전으로 업데이트되어 Geode가 그 버전을 지원하면, `mod.json`의 `geode`/`gd` 값만 바꿔 다시 빌드하면 됩니다.
